# SP11 — forge:maintain: dependency cadence + CVE triage

**Ticket:** #14 · **Branch:** `feat/14-maintain` · **Spec:** §4 item 9, rollout row 11 (size S). The last rollout epic.

The cms #70 lesson as platform law: dependency updates are **batched routine work, not a PR queue**. Patch/minor = one batch, auto-verified, one PR. Majors = bundled into one coordinated upgrade ticket, **never merged individually**. CVE advisories get a response SLA, not a backlog.

## Tasks

- [ ] T1 — Outdated scan: `plugin/scripts/care/maintain.mjs` — read package.json (deps + devDeps), query the npm registry (injected fetch; same zero-dep REST approach as depguard), classify each update patch/minor/major from semver distance. npm-family repos only; teaching error otherwise (same pattern as the graph's TS-only rule).
- [ ] T2 — Batch plan: `planBatch(outdated)` — patch+minor into one batch (branch name `chore/<n>-dep-batch-<date>`, the bump list, the verify requirement); majors listed separately with their changelog links, flagged for ONE coordinated ticket. CLI `plan` mode prints both; `--json` for tooling.
- [ ] T3 — CVE triage: `advisories` mode — `gh api /repos/{o}/{r}/dependabot/alerts` (teaching warning when alerts are disabled), map severity → SLA (critical 24h · high 72h · moderate 7d · low next-maintain), emit ticket-ready lines with deadlines from the alert's own createdAt.
- [ ] T4 — Skill: `plugin/skills/maintain/SKILL.md` — the cadence ritual: scan → batch branch → bump patch/minor → verify → one PR (normal ship gates); majors → one coordinated upgrade ticket via triage; CVE SLA table; runs on demand or scheduled (cron/CI is consumer wiring, the skill documents the hook).
- [ ] T5 — Tests + live dogfood: classification/batch/SLA against fixtures (injected fetch/exec); live `plan` run against this repo's real package.json + registry.

**Files:** plugin/scripts/care/maintain.mjs, plugin/skills/maintain/SKILL.md, docs/README.md

## Acceptance criteria

- AC-11.1 — outdated classifies patch/minor/major correctly from registry data, tolerates missing/unpublished packages, and refuses non-npm repos with a teaching error.
- AC-11.2 — the batch plan puts every patch/minor into one batch and every major into the coordinated-ticket list; a major can never appear in the batch.
- AC-11.3 — advisories map severity → SLA deadline computed from the alert's createdAt; disabled-alerts responds with the enable hint, not a crash.
- AC-11.4 — the skill states the laws: batched + auto-verified + one PR, majors bundled never individual, SLA table present.
- AC-11.5 — live: `maintain.mjs plan` runs against this repo's real dependencies and produces a coherent plan (or a clean "everything current").

## Out of scope

- Auto-merging the batch PR (L2 automation — `policy.autoApprove` ladder, owner enables later).
- Non-npm ecosystems (pip/cargo/go) — same adapter pattern as deploy stacks; add when an owner repo needs one.
- Scheduled-run wiring (GitHub cron workflow) — one workflow line for consumers, documented in the skill; forge itself runs on demand.
