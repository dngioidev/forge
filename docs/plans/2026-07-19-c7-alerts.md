# C7 — alerts

**Ticket:** #77 (board #12) · **Epic:** #56 · **Branch:** `feat/77-alerts` · **Spec:** forge-control §3c.

Get told when something goes wrong. Watch each repo's journal tail for failure-kind events + control sessions with a stale heartbeat; surface new ones as a red banner + alerts feed in the control tab + an opt-in Windows toast. **Honest limit:** local, best-effort-loud — not push-to-phone (that stays the Firebase step). Console open or toast enabled required.

## Tasks

- [ ] T1 — `console/lib/alerts.mjs`: `ALERT_KINDS` (gate-fail, cmd-fail, blocked-edit, backend-fallback, incident, respond-open) + pure `deriveAlerts({repos, sessions, now, staleMs, windowMs})` → alerts `{id, kind, repo, ticket, ts, severity, message}`, stable ids, newest-first; stale = alive session with `lastHeartbeat` older than `staleMs`. **Files:** console/lib/alerts.mjs
- [ ] T2 — `console/lib/toast.mjs`: opt-in `notify(title, body, {enabled, spawnFn})` — dependency-free Windows NotifyIcon balloon via PowerShell; no-op when disabled; best-effort (swallows errors); spawn injected. **Files:** console/lib/toast.mjs
- [ ] T3 — `console/serve.mjs`: `/api/control/state` gains `alerts` (control sessions + a light journal read per configured repo → `deriveAlerts`); newly-seen alert ids fire a toast when enabled, deduped by an in-memory seen-set across polls; a repo that errors doesn't sink the response. **Files:** console/serve.mjs
- [ ] T4 — `console/web/app.js` + `index.html`: control tab red banner when any active alert + an alerts feed (kind · repo · ticket · age). **Files:** console/web/app.js, console/web/index.html
- [ ] T5 — tests + dogfood: `deriveAlerts` kinds/stale/ids/degrade; `toast` disabled no-op + enabled one-call + error-swallow; `/api/control/state` alerts + Host guard; banner render. Live dogfood: seed a failure journal + a stale session, hit the endpoint, and fire one real toast. **Files:** tests/console/alerts.test.mjs

## Acceptance criteria

- AC-C7.1 — `deriveAlerts` turns failure-kind journal events (within the window) + stale-heartbeat alive sessions into alerts with stable ids; non-failure kinds / fresh sessions → none; partial input never throws.
- AC-C7.2 — `/api/control/state` includes the alerts feed; Host guard still applies; a repo error doesn't sink the response.
- AC-C7.3 — `toast.notify` is a no-op when disabled and (enabled) issues exactly one dependency-free PowerShell notification per call; errors swallowed; a new alert id fires at most one toast.
- AC-C7.4 — the control tab renders the red banner + alerts feed; no alerts → no banner.

## Out of scope

Quota panel (C8); true push-to-phone (Firebase). Alerts are best-effort local, documented as such.
