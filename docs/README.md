- [Tokenize-then-judge argv model](spikes/2026-08-13-argv-tokenize-model.md) — #451: designs an argv tokenizer to replace the denylist hook's regex-over-text rules, bash-verified against real word-splitting/`--`/env-assignment/NUL/nested-subshell semantics; recommends lexical (no-filesystem) `..` normalisation with the judge applied to the normalised path so `AC-446.1` is preserved, recording the tempting leading-component variant as rejected for regressing it. Answers the ticket's question honestly: **one rewrite does not retire six tickets** — #454/#456 close cleanly, #451 closes with a real residual limitation (pnpm's symlinked `node_modules` makes the lexical-vs-physical `..` gap reachable with no attacker involved), and #449/#452/#448 are each partial for different reasons. Its sharpest finding is that tokenization *exposes* a previously-unnamed question about what "safe target" means: `AC-446.6` passes today only via an over-block accident, so a faithful tokenizer changes what that test actually checks. A rule reconciling it with `AC-446.1` does exist (judge absolute paths by their leading component — verified across the pinned corpus with zero divergences, and independently re-derived by the security gate over a larger superset against the real `check()`) but costs spelling-dependent false positives, making this an owner semantics decision to settle before the Phase 2 port rather than a blocker on it. Also turns up a seventh live bypass (#459, `rm -r$(true)f`). Recommends a Phase-1-only tokenizer module (#457) over committing to the rewrite up front, given the guard fails open at the agy host and no host auto-approves any of these commands.
- [agy file-write gating](spikes/2026-08-13-agy-file-write-gating.md) — #436: re-verifies the agy adapter on v1.1.12 (up from v1.1.7) and empirically confirms the `run_command`-only PreToolUse matcher is forge's own choice, not an agy limit. AC.1: the host-level hook-timeout fail-open reproduces across a representative multi-call session and every tool type the matcher covers, with a non-deterministic ~10-15s cutoff rather than a clean 10s boundary. AC.2: unlike `run_command` (which has agy's own native `permissions.allow`/`command(<target>)` wall), `write_to_file` has **no independent native approval gate** — headless writes succeed with zero prompting whether or not forge's hook is present. AC.3 proposes, without choosing, four candidate rule shapes for a path+content payload (path denylist, overwrite-of-protected-config, content-signature, accept-the-gap), each weighed against `denylist.mjs`'s own "targeted backstop, not a sandbox" discipline. AC.4 concludes widening the matcher alone (no paired rule) is actively counterproductive — it only adds fail-open surface for zero gating benefit — and files the scoped decide-then-design follow-up as [#477](https://github.com/dngioidev/forge/issues/477). Also surfaces and separately files an unplanned, orthogonal finding: a `hooks.json` command-quoting bug that silently breaks forge's own installed `run_command` hooks on Windows/agy 1.1.12 ([#478](https://github.com/dngioidev/forge/issues/478)).

## Decisions (ADRs)

- [ADR-0001 — Status field options](decisions/0001-status-field-options.md) — built-in Status options are GraphQL-mutable but replacement mints new IDs; init replaces on fresh (empty) projects only, maps-as-is on live boards.
- [ADR-0002 — Console/control distribution](decisions/0002-console-control-distribution.md) — *(superseded by ADR-0003)* the console + control plane ship as repo tooling run from a checkout, not in the packaged plugin (#91).
- [ADR-0003 — Remove forge-control + console](decisions/0003-remove-control-console.md) — the local control plane + console are removed (unused for a solo interactive workflow; token/scope reduction). Preserved in the v0.5.0 tag; the pipeline (skills/board/gates/care) is unaffected (#95).
- [ADR-0004 — Remove the multi-backend plane](decisions/0004-remove-multi-backend-plane.md) — the CLI role-swap / multi-backend plane (Plane B) is removed as unwired dead weight; role subagents stay Claude-native. Preserved in the v0.5.0 tag (#99).
- [ADR-0005 — Local self-hosted runner](decisions/0005-local-self-hosted-runner.md) — PAT/secret model, sharing path, isolation, OS coverage, and advanced-CI decisions for the local self-hosted runner (epic #180).
- [ADR-0006 — Runner fleet cockpit](decisions/0006-runner-ui.md) — a native PySide6 (Qt) desktop "cockpit" for the local self-hosted runner fleet: Python 3.12 + `uv`, shell-out-only + WSL2 interop, PAT-free read-only default, in-repo at `tools/runner-ui/` (epic #262).
- [ADR-0007 — Cross-GAI: MCP-first core + host adapters](decisions/0007-cross-gai-mcp-first.md) — invert forge into a host-agnostic engine + per-host adapter emission; full parity on Antigravity (`agy`, proven), auto-merge Claude-only by policy, Codex deferred to #292 (epic #174).
- [ADR-0007 agy-adapter reference](decisions/0007-agy-adapter/README.md) — the verified-working spike output (`mcp_config.json`, `hooks.json`, deny/capture shims) that `forge init --host agy` productizes (#174).
- [ADR-0008 — Cockpit local web app](decisions/0008-cockpit-local-web-app.md) — *(Accepted)* re-architect the cockpit off LGPL PySide6 into a permissive localhost backend + browser UI + xterm.js terminal; supersedes ADR-0006 Decision 1 (UI approach). Delivered: FastAPI backend (#351), loopback hardening (#352), PTY-over-websocket bridge (#353), PySide6/PyInstaller removal (#355); the browser UI (#354) is the remaining piece (#344).
