Scores two remaining pairing strategies against a 19-case bash-verified corpus: nesting-depth-aware group *detection* (no content classification) closes every known bypass with one fewer false positive than the escalation's own "no pairing" option, at the same low iterative cost; nesting-aware pairing *with* alternative-content classification is the only prototype that also clears the known `git push origin {main,develop}` false positive, but reproduces the original removed implementation's defect-3 stack-overflow class on a 20k-deep nested input within ~20 minutes of adversarial self-testing, disqualifying it as prototyped. - [Hooks/scripts resolution](spikes/2026-08-16-hooks-scripts-resolution.md) — #519 (spike for #484, `esc-484-msrowtoy`): establishes that hooks and `scripts/**` driver invocations share one root mechanism (`${CLAUDE_PLUGIN_ROOT}` template substitution against the installed cache, never the working tree — verified empirically via a live `Skill` invocation and this session's own empty `CLAUDE_PLUGIN_ROOT` env var), but genuinely diverge in available fixes because only `scripts/**` invocations are agent-typed Bash commands an operator can redirect in the moment. Surfaces a mechanism absent from the original escalation — Claude Code composes project-level and plugin-level hooks in parallel rather than overriding — and recommends it for `hooks/**` (additive, closes the new-rule-not-yet-cached gap, Windows-safe) paired with a documented working-tree-path convention for `scripts/**` (no mechanism found that beats today's status quo without a real cost). Names three specific follow-ups the time-box didn't reach rather than forcing a false full resolution.
