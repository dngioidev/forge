# Driver scripts (the executable spine)

Reference for `plugin/skills/autopilot/SKILL.md` § Driver scripts (#467 AC-2 — relocated,
not deleted: this is the same content that used to sit inline). The loop's own copy stays a
short summary + this link — the orchestrator invokes these via CLI/MCP and never needs the
signature/rationale detail below to run the loop; it's here for anyone debugging or
extending a driver script.

The loop is prose the orchestrator runs, but its mechanical decisions are real, tested scripts under `${CLAUDE_PLUGIN_ROOT}/scripts/autopilot/`:

- `select.mjs` — `selectNext(tickets)` / `--dry-run`: the selection order + the triage/deliver/resume decision (§ selection). Pure, so the order is testable. `selectNext`'s `dependencyIssues` param (#487, § Selection's "sequenced behind #N" resting state) excludes a ticket with an unresolved `lib/dependencies.mjs` record regardless of board status, mirroring `pendingIssues`'s #499 exclusion; `main()`'s IO wrapper calls `resolveDependencies(cwd,{gh})` before every selection so a dependency that closed since the last pass clears itself first. `normalize()`'s `kind` field (threaded into § Rate-budget preflight's post-selection `evaluateRateBudget` call) is now sourced from the board `type` field FIRST (#530 — `epic`/`item`/`bug`/`test` on this board, ~100% coverage, set via `create.mjs --type` which needs Projects-v2 board-write access), falling back to `ticketKind(title)` (#526 — reads a ticket title's leading prefix, returns `'docs'`/`'spike'`/`null`) only when `type` is unavailable. Measured against 8 real board titles, the old title-only classifier hit 2/8; the board-type-first classifier hits 8/8 (#530 evidence table) — closing the #526 trust-boundary finding (title text is freely issue-write-editable; the board field isn't).
- `merge.mjs` — `evaluateMergeBar(signals)` + `runMerge(ctx,{issue,pr,signals,mode,outageAttempt,maxOutageAttempts})`: the auto-merge bar. Fail-closed — a missing signal is red; `features.autopilotAutoMerge:false` **or** the preflight's `mode:'pr-only'` parks at the PR. This is where "nothing merges on red" lives. `runMerge` is the **canonical, enforced merge entry point**, exposed to hosts as the `autopilot_merge` MCP tool (forge-core) so the live merge is executed through the bar by construction — never via a raw `gh pr merge`. `ciGreen(gh, pr, {freshState})` (#407 AC.2) accepts the `forge-ci` monitor's last observed transition (read from `ctx.cwd` via `monitors/ci-watch.mjs` `loadCiWatchState` when `runMerge` has a `cwd`); a very recent (`isFreshGreenTransition`, default 20s) known-green reading for the SAME pr satisfies the check without a redundant GraphQL re-fetch — reducing the 3 idle CI-status pollers per ticket lifecycle (forge-ci monitor / the delivery subagent's own `--watch` / this pre-merge re-check) to effectively 2. Anything less than an exact fresh match (wrong pr, stale, non-pass, or no `cwd`/file at all) falls straight through to the unchanged real re-fetch — the mandatory pre-merge green confirmation itself is never skipped, only its network cost sometimes is. `classifyCiFailure(gh,{branch})` + `forceNewSha(execRun,{base})` (#408, § Auto-merge item 4) are the outage classification + the bounded fresh-SHA recovery `runMerge` runs before treating a real CI red as a gate failure — journaled (`gate-fail`, `outage:true`) so the run report can tell a real fix wave from GitHub being down twice.
- `preflight.mjs` — `mergeAuthPreflight({authorized,config})`: the run-start merge-authorization decision (§ Merge-authorization preflight). Pure — returns the effective merge `mode` (`auto-merge` only on an explicit in-session grant + config-enabled; else `pr-only` with the notice to surface). `startRun` records it into `run.json`; `runMerge` gates on it. This is what stops an unattended run from delivering a whole ticket and then silently wedging at the first merge (#316).
- `ratebudget.mjs` — `shouldPauseForBudget(budget)` (§ Rate-budget preflight, #407): the pure threshold decision over a `rateBudget()` reading, mirroring `sessionpause.mjs`. `evaluateRateBudget(gh, {lowWater, recentDeltas, kind})` is the IO wrapper the orchestrator calls at run start and every `budgetCheckDue(iterations)`-th iteration (every iteration, `DEFAULT_CHECK_EVERY_N = 1`, #517) — the run-start call has no ticket yet so no `kind`; every periodic recheck thereafter runs after selection and threads the just-selected ticket's `kind` (board `type`-derived as of #530 — see `select.mjs` above). A FAILED check degrades to "don't pause" (today's reactive per-call retry), never a hard block. `estimateTicketCost(recentDeltas, kind, fallback = DEFAULT_LOW_WATER)` (#517, kind-aware since #526) derives the effective low-water threshold: a `kind` that's a `KIND_COST_ESTIMATES` key (`{ docs: 975, spike: 3457 }` — still the title-prefix vocabulary, unchanged by #530; see its docblock for why the board `type` vocabulary has no entries yet — no `docs`/`spike` type option exists, and #462/#438 prove a single board type spans a >5x measured range) short-circuits to `Math.max(KIND_COST_ESTIMATES[kind], UNATTRIBUTED_DRAIN_FLOOR)` (1500 — floors a known-cheap kind against idle/background drain), ignoring `recentDeltas`/`fallback`; any other `kind` — as of #530, every real board-`type`-derived kind (`item`/`bug`/`test`/`epic`) — falls through to the unchanged #517 path — the max of this run's own recent GraphQL-remaining deltas, falling back to the raised `DEFAULT_LOW_WATER` (4993, the measured worst-case single-ticket cost) when there's no history yet. `ledger.mjs` now also owns `applyBudgetReading`/`recentBudgetDeltas`/`recordBudgetReading` for the reading history this feeds from.
- `envpreflight.mjs` — `evaluateEnvPreflight(probes)` (§ Environment preflight, #504): the pure decision over already-run probe results, mirroring `mergeAuthPreflight`/`shouldPauseForBudget`. `probeEnv(ctx)` is the IO wrapper the orchestrator calls at run start (before `startRun`): six probes — `gh`/`node`/`pnpm` resolvable, `node_modules` present, board Status option keys vs. `select.mjs`'s `TIER`/`SKIP`, statusline plugin path on disk — each run through a shared `runProbe` wrapper so a probe that throws degrades to a warning, never a hard failure of the whole preflight. `formatBlockers(blockers)` renders the numbered list with fixes the orchestrator prints on `verdict:'no-go'`.
- `ledger.mjs` — the run ledger (`.forge/autopilot/run.json`): `applyOutcome`/`applyFiled`/`guardTripped`/`nextIteration`/`renderReport`, plus `ledger.mjs report`. `nextIteration(run, boardSize)` is the per-iteration **runaway backstop** the loop calls first each iteration — the real caller for `guardTripped` (halt + escalate on trip; #317). The resume point too. `startRun(cwd, {..., boardSize})` persists that board size once as `run.boardSizeAtStart` — the cap anchor `nextIteration`/`guardTripped` prefer over the live count (#488, § Stop conditions & safety rails).
- `watchdog.mjs` — `resolveReturnedTicket({outcome,pr,ciGreen,mergeMode})`: the return-then-resume watchdog (§ Return-then-resume watchdog). Pure — the loop runs it on **every** subagent report so an `awaiting-merge` on a green PR is re-driven to the merge bar or surfaced, never silently parked (#319); a non-conforming report (missing outcome, or free text) with a PR already open respawns instead of being recorded as resolved (#464), or funnels straight to the merge bar if the caller's own observed state already shows it green + authorized; the same non-conforming report with **no PR at all** escalates instead of respawning (#522) — unrecoverable, working-tree state can't be observed from here.
- `newwork.mjs` — `fileWork(ctx,{title,kind,from})`: files a linked follow-up (bug/spike/item) mid-run.
- `perms.mjs` — **Claude-only**: prints the local Claude settings allowlist autopilot needs to run continuously (non-destructive; opt-in). agy pre-authorizes via a hook instead — see § Permissions.
- `sessionpause.mjs` — `shouldPause({usedPercentage,thresholdPct})` (§ Session-window self-pause): the pure threshold decision (default 90), plus `evaluateSessionPause(cwd)`, the IO wrapper that reads `.forge/autopilot/usage.json` (written by `statusline.mjs`) + `autopilot.sessionPauseThresholdPct` config and degrades to "don't pause" on any missing/stale/unconfigured input.

Two more supporting pieces, not autopilot-only but load-bearing for #407:

- `monitors/ci-watch.mjs` — besides its usual background-poll job (§ Monitor notifications), it now writes its every-poll observation to `.forge/autopilot/ci-watch.json` (`writeCiWatchState`/`loadCiWatchState`) so `merge.mjs`'s `ciGreen()` in a DIFFERENT process (the delivery subagent) can read a fresh transition back (#407 AC.2). Best-effort — a write failure never crashes the monitor.
- `monitors/agents-watch.mjs` (#505, epic #503) — `classifyLiveness({record,now,thresholdMs})`: the pure liveness decision (§ Monitor notifications, `forge-agents`), no IO, injected clock. `writeAgentHeartbeat(cwd,{...})`/`readAgentRecords(cwd)`/`clearAgentHeartbeat(cwd,id)` are the IO wrappers: the first is called by the delivery subagent itself (best-effort, never-fail-the-caller); the other two are the monitor's own read and the orchestrator's post-outcome cleanup. `poll(cwd,prevStatuses,{now,thresholdMs})` is the IO wrapper the CLI's poll loop calls, diffing against a `Map<id,status>` threaded across polls (mirrors `ci-watch.mjs`'s `prev`) so a line fires only on a transition, never per poll.
- `lib/board.mjs` — `getRepoInfo(gh)` / `getProjectFields(gh, projectId)` are now memoized per `gh` instance (#407 AC.3): repeat calls against the same injected `gh` (a long-lived process — notably the forge-core MCP server, which resolves one `gh`/ctx for its whole session) are served from cache instead of re-fetching. Pass `{refresh: true}` after a mutation that changes what a fresh read must reflect (e.g. `init.mjs`'s post-field-creation re-discovery).
- `lib/outbox.mjs` (#414) — the local GitHub outbox: `enqueue`/`pendingCount`/`drain`/`attemptOrDefer`, `node lib/outbox.mjs drain` as a thin CLI. The five queue-eligible `board/*.mjs` `run*` functions call `attemptOrDefer` themselves (§ Monitor notifications, `forge-outbox`) — this module is never called directly by the orchestrator except to read `pendingCount` for the report line / `board_status` field, or to trigger an opportunistic drain.
- `lib/lock.mjs` (#414, per #387's design) — `acquireLock(path)`/`isStale(lock)`: the shared exclusive-lockfile helper (`fs.open(path,'wx')`, `{pid,startedAt,hostname}`, PID-liveness + age-staleness reclaim, `release()` in try/finally). `lib/outbox.mjs` is its first real consumer (`.forge/autopilot/outbox.lock`); #387's eventual `run.lock` should reuse it rather than duplicate the idiom.

The orchestrator holds the ship/gate/reviewer/security verdicts and passes them to the merge bar; the scripts never spawn subagents or drive the loop themselves.
